# FastConv_SystemVerilog

## Overview

FastConv is an optimized 2D convolution architecture (Toom-Cook and variants) described in SystemVerilog. The repository includes synthesizable RTL, test data packages, automation scripts, and synthesis materials used to explore different window and channel configurations. Use it as a foundation to understand the complete pipeline: hardware generation, functional simulation, and timing/power closure.

## Dissertation Reference

The Git tag `dissertation` points to the commit hash that contains the exact code version used in the dissertation.

## Repository Structure

- `rtl/`: SystemVerilog modules organized by function (control, memories, multipliers, muxes, complete systems). Each subfolder contains a `README.md` describing the module and its ports.
- `data/`: sets of weights/feature maps and configuration files generated by the `fast-conv` utility.
- `scripts/`: automation tools to build FastConv projects, launch simulations/syntheses in batch, and consolidate reports.
- `rtl/conv*/synthesis/<configuration>/`: per-RTL ASIC flow inputs and generated Genus, Xcelium, and Joules artifacts.
- `report/`: repository-wide consolidated CSV/Markdown results; see [`report/README.md`](report/README.md).
- `rtl/conv*/report/`: consolidated results scoped to one convolution size.
- `contrib/`: archived previous experiments, prototypes, and reference materials preserved for consultation.
- `copy-sv.sh`: utility to automatically import new SystemVerilog artifacts from the `fast-conv` generator into the `rtl/` tree.

## Repository-level Makefile

The root `Makefile` provides short entry points for the common report, RTL
simulation, and ASIC synthesis/simulation/power tasks. Run `make help` for the
available targets and examples. Common report commands are:

```bash
make report                    # regenerate consolidated reports
make report INCLUDE_ARCHIVED=1 # include archived variants
make metrics                   # calculate dataset MAE/RMSE metrics
```

Run one RTL simulation by selecting the architecture and, where needed, its
algorithm, multiplier count, and prefetch-column count. For example:

```bash
make sim ARCH=conv2x2 VARIANT=std
make sim ARCH=conv2x2 VARIANT=trunc-column NUM_MULT=8
make sim ARCH=conv3x3 ALGORITHM=ifn9 NUM_MULT=6 PREFETCH_COLUMNS=2
make sim ARCH=conv4x4 ALGORITHM=tcn16 NUM_MULT=6 PREFETCH_COLUMNS=3
```

`make sim-all` runs the active root RTL simulation cases and stores their
results under `simulation_results/`. Long simulations and all ASIC EDA targets
must be run from a `tmux` session. ASIC configurations are selected by their
exact directory name under `rtl/<architecture>/synthesis/`:

```bash
make list-configs ARCH=conv4x4
make synth ARCH=conv4x4 CONFIG=<configuration-directory>
make gate-sim ARCH=conv4x4 CONFIG=<configuration-directory>
make power ARCH=conv4x4 CONFIG=<configuration-directory>
make flow ARCH=conv4x4 CONFIG=<configuration-directory>
```

`make flow` runs synthesis, gate-level simulation, and power sequentially, and
stops if a stage fails. Per-configuration flow artifacts remain in that
configuration's `rtl/<architecture>/synthesis/<configuration>/` directory.
The Makefile delegates to the existing architecture runners; it does not
replace their scripts or change their result formats.

## Where to find results

There are two levels of reports:

- **Consolidated comparison tables:** `report/` contains the repository-wide
  `report.md` and CSV tables generated by `scripts/report.py`. The corresponding
  architecture-specific reports are in `rtl/conv2x2/report/`,
  `rtl/conv3x3/report/`, and `rtl/conv4x4/report/`. Historical snapshots are
  kept separately in `report/legacy/`.
- **Raw ASIC flow evidence:** for a specific RTL/configuration, open
  `rtl/conv*/synthesis/<configuration>/`. Genus reports and mapped netlists are
  under `logical/results/` (detailed reports are in
  `logical/results/reports/`); gate-level simulation logs and activity files
  are under `sim/`; and the Joules summary is
  `power/power_evaluation.txt`, with supporting files under `power/`.

The configuration directory identifies the RTL variant and, where applicable,
its precision. For example, a directory ending in `-nbits16` is a separate
16-bit flow and does not replace the preserved 20-bit configuration without
that suffix. A prepared configuration is not evidence that its flow completed;
check its stage logs/results and `report/flow-status.csv`. Regenerate the
consolidated tables with `make report`.

## Prerequisites

- Git and Python 3.8+ (to run the automation scripts and the `fast-conv` utility).
- The `fast-conv` CLI installed in the PATH to generate new datasets/RTL.
- ModelSim/QuestaSim (or another `vsim`-compatible simulator) for functional simulation.
- Cadence Genus (logic synthesis) and Cadence Xcelium (post-synthesis simulation) configured in the environment.
- Optional Verilator for static linting via `veridian`.

## Functional Simulation (ModelSim/QuestaSim)

1. Choose the configuration under the relevant `rtl/conv*/synthesis/` directory. Adjust its `list-file.txt`, `list-define.txt`, `top-module.txt`, and `testbench-file.txt` when testing another variant.
2. Go to `rtl/system/` and run the TCL compile/simulate script:
   
   ```bash
   cd rtl/system
   vsim -c -do sim.tcl
   ```
3. The script prepares the `work` library, compiles listed packages, builds the testbench `tb`, and runs 7000ns of simulation. Use `vsim` without `-c` to open the graphical interface, inspect waveforms (`wave.do`), and debug.
4. For larger campaigns, use the architecture-local wrappers and the collectors in `scripts/`. The old `multiple-do.sh`, `multiple-make.sh`, `multiple-synth.sh`, `multiple-power-eval.sh`, and `time-arch.py` scripts remain only for legacy directory layouts.

## Logic Synthesis and Power Analysis (Cadence Genus)

1. Select or create a configuration under `rtl/conv*/synthesis/<configuration>/` and verify its `list-file.txt`, `list-define.txt`, top module, testbench, and precision parameters.
2. Run the logical synthesis entry point from the configuration directory:

   ```bash
   cd rtl/conv*/synthesis/<configuration>/logical
   bash run.sh
   ```
   
   The runner invokes Genus and writes reports/netlists under `results/`.
3. For power analysis, enter `rtl/conv*/synthesis/<configuration>/power/` and run its entry point:

   ```bash
   cd rtl/conv*/synthesis/<configuration>/power
   bash run.sh
   ```
4. Post-synthesis simulation runs from the configuration's `sim/` directory with `bash run.sh`; the runner invokes Xcelium (`xrun`) using the matching mapped netlist, sources, and defines.
5. Consolidate RTL-local metrics with `scripts/report.py`, which reads executed projects from `rtl/conv*/synthesis/` and produces aggregate CSV/Markdown tables in `report/`, plus a scoped report under each `rtl/conv*/report/`. Projects under `archive/` are excluded by default; pass `--include-archived` when a historical comparison needs them. Historical consolidated tables are kept in `report/legacy/`. Ratios against a naive synthesis are generated only when `--naive-synthesis-dir PATH` is supplied.
