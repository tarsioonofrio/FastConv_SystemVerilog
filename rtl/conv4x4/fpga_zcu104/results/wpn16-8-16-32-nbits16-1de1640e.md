# WPN16 FPGA campaign: 8, 16, and 32 MACs at 16 bits

## Result

The full flow was attempted for all three WPN16 variants on the ZCU104
(`xczu7ev-ffvc1156-2-e`) at the common 317 MHz operating point. Only the
8-MAC design completed a valid post-route functional simulation and P3F power
analysis. The 16- and 32-MAC designs were implemented and simulated, but both
produced incorrect final outputs in the post-route functional netlist. The
32-MAC implementation additionally failed the 317 MHz timing constraint.

| MACs | LUT | FF | DSP | BRAM | Routed WNS | Timing @317 MHz | Post-route functional golden | Valid P3F |
| ---: | ---: | --: | --: | ---: | ---------: | :-------------- | :--------------------------- | :-------- |
| 8  | 6,401 | 2,151 | 8  | 0 | +0.001 ns | Pass | Pass; 2,700 outputs, 0 mismatches | Yes |
| 16 | 7,366 | 2,503 | 16 | 0 | 0.000 ns | Pass, zero rounded slack | Fail; 2,700/2,700 mismatches | No |
| 32 | 8,094 | 3,193 | 32 | 0 | -0.277 ns | Fail; 216 endpoints, TNS -22.298 ns | Fail; 2,700/2,700 mismatches | No |

The resource figures are from the routed Vivado `report_utilization`. No BRAMs
were inferred; all three consume the expected number of DSP blocks. Percent of
the XCZU7EV device used by LUT/FF/DSP respectively was 2.78/0.47/0.46% for
8 MACs, 3.20/0.54/0.93% for 16, and 3.51/0.69/1.85% for 32.

## Valid 8-MAC result

The 8-MAC design passed the post-route functional Xcelium simulation using the
canonical 16-bit truncated WPN16 package. The test reported:

```text
STREAM_COLUMN_POWER_PASS writes=2304 physical_words=9216 final_words=2700 mismatches=0 active_cycles=8843
```

Vivado imported the post-route functional SAIF with 100% direct mapping
(`13,610 / 13,610` nets) and reported High confidence. This is P3F, a
post-implementation functional-activity estimate; it is not a board power
measurement and does not include timing-glitch activity from SDF.

| Corner | Dynamic | Device static | Total on-chip | Confidence |
| :----- | ------: | ------------: | ------------: | :--------- |
| Typical | 0.550 W | 0.595 W | 1.144 W | High |
| Maximum | 0.550 W | 0.818 W | 1.368 W | High |

Typical dynamic breakdown:

| Component | Power |
| :-------- | ----: |
| Clocks | 0.027 W |
| CLB logic | 0.070 W |
| Signals | 0.102 W |
| DSP | 0.014 W |
| I/O | 0.337 W |

The P3F estimate is for the present top-level, which still has physical FPGA
I/Os. I/O accounts for 0.337 W of the 0.550 W dynamic estimate, so this number
should not be described as core-only power. The static component is the
Vivado device estimate, not a measurement of the board.

Using 8,843 active cycles at the common 317 MHz comparison frequency gives
27.896 us/job. With 145,800 equivalent operations per job (one MAC = two
equivalent operations), derived results are:

| Metric | Value |
| :----- | ----: |
| Active-job throughput | 5.227 GOPS |
| Dynamic energy/job | 15.34 uJ |
| Total on-chip energy/job | 31.91 uJ |
| Dynamic-power-normalized efficiency | 9.50 GOPS/W |
| Total on-chip efficiency | 4.57 GOPS/W |
| Dynamic energy/op | 105.2 pJ/op |
| Total on-chip energy/op | 218.9 pJ/op |

These are derived from Vivado power estimates and the simulated active-job
latency. The total values include the static device estimate and the current
top-level I/O model.

For comparison only, the 8-MAC vectorless P0 typical report was 0.410 W
dynamic, 0.594 W static, and 1.004 W total, with Low confidence. P0 is not the
selected activity-based result.

## 16- and 32-MAC outcomes

Both designs completed synthesis, implementation, routed reports, and a
post-route functional Xcelium run. Each run reached `p_end`, captured a DUT
SAIF, and then failed the golden check with all 2,700 final outputs mismatching.
The captured DUT SAIF files are retained for diagnosis but were not imported
into Vivado and are invalid for power reporting. A diagnostic run that moved
the output scoreboard sampling to the falling edge retained the same mismatch
count for 16 MACs, so this was not resolved as a simple output-sampling race.
The underlying post-route functional mismatch remains unexplained.

| MACs | RTL/Verilator active cycles | P0 Typical dynamic / static / total | P0 confidence | P3F power |
| ---: | --------------------------: | :--------------------------------- | :------------ | :--------- |
| 16 | 6,547 | 0.451 / 0.594 / 1.045 W | Low | Not valid; functional golden failed |
| 32 | 5,395 | 0.568 / 0.595 / 1.162 W | Low | Not valid; functional golden and timing failed |

P0 figures are vectorless estimates retained as implementation diagnostics.
They must not be used to calculate accepted GOPS/W, energy/job, or pJ/op for
these designs. The RTL cycle counts likewise are not promoted to implemented
performance results while the post-route functional outputs fail.

## Interpretation

The flow is complete as an evidence-producing campaign, but it does **not**
yield three comparable valid P3F points. At present, 8 MACs is the only
variant with post-route functional correctness and activity-based power; 16
MACs has a marginal timing pass but an unresolved functional mismatch, while
32 MACs has both an unresolved functional mismatch and a routed timing failure.
Do not compare their vectorless P0 estimates as if they were equivalent to
P3F.
