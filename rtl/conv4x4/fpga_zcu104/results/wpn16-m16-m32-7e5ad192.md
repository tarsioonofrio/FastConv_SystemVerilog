# WPN16 m16/m32 FPGA campaign

This is the first full Vivado/Xcelium run for the two higher-parallelism WPN16
variants. It was run on Paxos from source commit
`7e5ad19297367bdec19ec02eac838b1e03db5024` with Vivado 2023.2 and Xcelium
23.03-s003, targeting XCZU7EV at the shared 317 MHz point. The canonical
WPN16 workload package was used unchanged. Raw campaign output is under
`../reports/wpn16-m16-m32-7e5ad192/`; DCP, functional netlists and SAIF files
remain on Paxos and are intentionally not committed.

| Variant | DSP | LUT | FF | BRAM | WNS @ 317 MHz | Post-route funcsim | P3F Typical dynamic / static / total |
| --- | ---: | ---: | ---: | ---: | ---: | --- | ---: |
| WPN16 m16 | 16 | 9,885 | 3,121 | 0 | +0.000 ns, 0 failing endpoints | PASS; 2,304 write beats, 2,700 final outputs, 0 mismatches | 0.816 / 0.596 / 1.412 W |
| WPN16 m32 | 32 | 10,877 | 4,040 | 0 | -0.594 ns, 659 failing endpoints | FAIL; 2,700/2,700 final outputs differ | Not valid; P3F was stopped before power import |

The m16 timing summary says all user-specified constraints are met; its clock
is reported as 316.957 MHz due to period rounding. The report also identifies
204 primary inputs without input delays and 108 outputs without output delays,
so timing evidence describes the constrained register-to-register paths, not
a fully specified external interface.

For m16, P3F passed both DUT-SAIF and top-SAIF simulations. The final Vivado
report matched 20,106/20,106 design nets; the DUT-only SAIF mapping matched
19,794/20,106 nets (98.45%). P3F Typical component power was clocks 0.036 W,
CLB logic 0.124 W, signals 0.196 W, DSP 0.019 W, and I/O 0.441 W. The large
I/O term reflects this top-level's exposed ports and the Vivado default I/O
model; it should not be described as isolated datapath power. Maximum-corner
P3F was 0.816 W dynamic, 0.822 W device static, 1.638 W total.

P0 vectorless references were generated for both variants. For m16, Typical
was 0.592 W dynamic / 0.595 W static / 1.187 W total; Maximum was 0.592 /
0.819 / 1.410 W. For m32, these vectorless-only values were 0.682 / 0.595 /
1.278 W Typical and 0.682 / 0.820 / 1.502 W Maximum. The m32 reports are
low-confidence vectorless estimates only; they are not comparable to valid
workload-driven P3F results.

The m32 core passes the local Verilator golden test (5,395 cycles to `p_end`,
8,100 valid writes, zero mismatches), but the post-route functional netlist
fails the canonical golden in Xcelium. Therefore its SAIF/power result must
not be used for energy, GOPS/W, or pJ/op until the netlist simulation is
understood and passes. The campaign runner correctly stopped at that gate.
