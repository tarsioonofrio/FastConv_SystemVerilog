# TCN16 truncated-weight workload, NBITS=20, without fractional weight bits

Canonical workload: 32x32 input, Cin=3, Cout=3, seed=0, NBITS=20 and
QUANT_BITS=8. Transformed weights are floor-divided by the TCN16 scale 576 and
stored as signed 20-bit integers. There are no additional fractional bits.

The package is generated by the `fast-convolution-rtl` simulator with:

```bash
python -m fast_convolution.cli \
  -p rtl/conv4x4/data/tcn16 sim normal \
  --image-side 32 -i 3 -o 3 -d 0 \
  --truncated-weight-transform --nbits 20 --no-c -n trunc-nbits20
```

The `const_data` sequence contains the feature-map data followed by the
floor-truncated transformed-weight words expected by the pretransformed-weight
column RTL. The separate `const_weight` array and `s.txt` are generated from
the same integer fixed-point model; the golden output does not include the
six fractional weight bits used by the earlier `trunc-frac6` experiment.

Against the canonical floating-point reference, this package has MAE=1.782811,
RMSE=2.856839, maximum absolute error=22.258493, and computed R2=0.742036
(the library summary reports R2=0.740552). This is expected for the
no-fraction TCN16 approximation and is not comparable to the higher-precision
frac6 package without accounting for the change in weight quantization.
